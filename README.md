# AFTER THE NUMBERS — v3.1

2026-09-10 · v3.0의 콘텐츠와 발행 구조를 유지한 모션·모바일 개편판

## 이번에 적용한 내용

- 첫 화면의 브랜드 글자가 순서대로 등장하고, 실적 선 다음에 전망 선과 전망 영역이 나타납니다.
- Rolling Forecast를 네이비 대표 사례로 강조했습니다.
- 모바일에도 네 가지 사례 그래프를 표시합니다. 전망 연결, 손익 증감, 판단 조건의 수렴, 예산·실적 차이를 각각 다르게 표현합니다.
- 그래프는 화면에 진입할 때 한 번 재생하고 완성된 상태로 남습니다.
- 섹션 제목과 글 목록에 짧은 등장 효과, 경력에 스크롤 진행에 반응하는 연결선을 적용했습니다.
- 사례 카드의 번호·제목·그래프와 상세 페이지에 같은 전환 이름을 지정했습니다. 지원 브라우저는 기본 페이지 이동 시 약 0.32초의 연결 전환을 사용합니다.
- 모바일 메뉴와 터치 반응을 개선했습니다. 긴 글 본문은 기존 읽기 흐름을 유지합니다.
- 기본 세로 스크롤과 링크 이동을 사용합니다. 스크롤을 가로채서 콘텐츠를 바꾸지 않습니다.

## ZIP 두 개의 용도

| 파일 | 용도 |
| --- | --- |
| `after-the-numbers-v3.1-full-source.zip` | 전체 보관·새 설치용. 운영 소스, 콘텐츠, 관리자 설정, 안내 문서와 생성된 `dist`를 모두 포함합니다. |
| `after-the-numbers-v3.1-github-update.zip` | **기존 v3.0 저장소 업데이트용.** 이번에 변경·추가된 파일만 담았습니다. 기존 글과 업로드 파일은 그대로 두고 적용합니다. |

두 ZIP 모두 압축을 열면 바로 프로젝트 루트의 파일들이 보입니다.

## 기존 v3.0을 GitHub에서 업데이트하기

1. `after-the-numbers-v3.1-github-update.zip`을 내려받아 압축을 풉니다.
2. GitHub에서 현재 사이트의 저장소와 배포 브랜치를 엽니다.
3. 저장소 첫 화면에서 **Add file → Upload files**를 선택합니다.
4. 압축을 푼 폴더 **안의 파일과 `scripts` 폴더**를 함께 올립니다. ZIP 자체나 바깥 폴더를 올리지 마세요.
5. 같은 경로의 파일을 덮어쓰는 하나의 커밋으로 반영합니다. 기존 파일 전체를 지울 필요가 없습니다.
6. 배포가 완료되면 홈페이지와 사례 상세 페이지를 새로고침합니다.

특히 새 `motion.css`와 `motion.js`를 꼭 함께 올려야 합니다. `scripts/validate-build.js`는 `scripts` 폴더 안에 있어야 합니다.

GitHub 업데이트용은 기존 v3.0의 `content`, `figures`, `admin`, `uploads`와 나머지 파일을 그대로 사용합니다. **빈 저장소에 설치하거나 v2.x에서 바로 올릴 때는 전체 소스를 사용하세요.** 전체 소스를 적용할 때도 기존 저장소에서 별도로 추가·수정한 게시글·도식·업로드 파일은 먼저 보관하고 최신 내용을 유지하세요.

## 기존 배포 설정

기존 GitHub 연결과 배포 브랜치를 유지합니다.

- 빌드 명령: `npm run build`
- 출력 디렉터리: `dist`
- Node.js: 20 이상
- 추가 패키지 의존성: 없음

GitHub 업데이트용에는 빌드 결과물인 `dist`를 넣지 않았습니다. 소스의 `index.html`은 빌드 템플릿이므로 파일을 직접 열면 완성된 사이트가 아닙니다. 빌드가 끝난 `dist/index.html`이 서비스됩니다.

직접 업로드 배포가 필요한 경우 전체 소스의 `dist` **안의 파일**이 공개 루트에 오도록 사용합니다. GitHub와 연결된 기존 사이트는 위의 GitHub 업데이트 방법을 사용하세요.

## 글을 발행하는 방법

기존 방식과 같습니다.

1. `/admin/`에서 기존 Pages CMS로 이동합니다.
2. `content/posts`에 Markdown 파일 한 개를 생성하거나 업로드합니다.
3. `content/POST_TEMPLATE.md` 형식을 사용하고 `draft: false`로 발행합니다.
4. GitHub 커밋에 따라 다시 빌드되면 홈의 최신 글, 전체 글 목록, RSS, 사이트맵에 반영됩니다.

공개 글에는 기존 정책대로 도식이 최소 두 개 필요합니다. 새로운 도식 토큰은 `figures/TOKEN.html` 파일도 함께 추가하세요. 관리자와 외부 CMS 연결 설정은 유지했습니다.

## 모션 동작과 확인 범위

운영체제/브라우저의 ‘동작 줄이기’ 설정을 따르면 모션을 해제합니다. JavaScript 또는 관련 API를 사용할 수 없어도 콘텐츠와 그래프의 기본 완성 상태를 표시합니다. 페이지 전환을 지원하지 않는 브라우저는 일반 링크 이동을 사용합니다. 구현 참고: [Chrome의 문서 간 View Transition 안내](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document).

이번 버전은 빌드, JavaScript 구문, 내부 링크·앵커·ID, SVG 참조, 반응형 규칙을 정적으로 확인했습니다. 모션 미지원, 동작 줄이기 전환, 키보드 포커스, 뒤로 가기 복원은 Web API 모의 환경에서 확인했습니다. 실제 브라우저 화면·휴대폰에서의 모션 품질, 외부 CMS 로그인과 공개 배포는 이번 작업에서 검증하지 않았습니다.
